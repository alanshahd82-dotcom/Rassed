# راصد — Rassed

نظام تدقيق وتتبع طلبات شركات التوصيل للتجار. راصد ليس نظام مبيعات؛ وظيفته الأساسية هي منع ضياع الطلبات ومطابقة كل حركة بين المتجر وشركة التوصيل.

## ما تم بناؤه

- لوحة تدقيق تعرض إجمالي الطلبات، الخارج، المسلّم، الراجع، والطلبات المتأخرة.
- شاشة Scan مع وضعَي `Sortie` و`Retour`، إدخال يدوي، ومنع تسجيل الحالة نفسها مرتين.
- سجل طلبات قابل للبحث والتصفية حسب الحالة وشركة التوصيل.
- مركز تنبيهات للطلبات المتأخرة والفروقات والحالات غير المعروفة.
- تحليلات أداء شركات التوصيل ونسب التسليم والـ Retour.
- تقارير وتصدير CSV قابل للفتح في Excel.
- تجربة RTL عربية متجاوبة مع تنقل سفلي على الهاتف وPWA قابلة للتثبيت.
- بيانات وهمية واقعية لمدن مغربية وشركات توصيل متعددة.

## البنية

- `index.html` — شاشات التطبيق وهيكله.
- `styles.css` — نظام التصميم والاستجابة للجوال.
- `app.js` — التنقل، التفاعل، Scan، الفلاتر، التنبيهات والتصدير.
- `data-source.js` — طبقة البيانات الحالية داخل الذاكرة و`localStorage`.
- `manifest.webmanifest` و`sw.js` — دعم PWA والعمل دون اتصال.

## مصدر البيانات

واجهة `window.RassedData` في `data-source.js` هي العقد الحالي بين الواجهة ومصدر البيانات. عند ربط Google Sheets لاحقًا، يتم استبدال تنفيذ `all`, `find`, `update`, `stats` بطلبات API مع الحفاظ على نفس الواجهة العامة، لذلك لا تحتاج شاشات التطبيق إلى إعادة بناء.
